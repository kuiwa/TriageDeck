实现：
- 新增 `AiGateway`（ai 模块）：用 JDK `HttpClient` 调 OpenAI 兼容 `POST {app.ai.base-url}/chat/completions`，`model/temperature=0/response_format=json_object`；方法与 `toFilterJson(question)`、`toBriefingJson(alert)`；未配置（enabled=false 或 mock 或 base-url/api-key 缺失）或调用失败返回 `Optional.empty()`，并打 `action=ai_gateway_*` 告警日志（不含 key/请求体）。
- `AiQueryService`：`enabled=false` → 503 `AI_UNAVAILABLE`；否则先模型解析 filter JSON，空则回退关键词规则；`explanation` 标注是否降级。
- `AiBriefingService`：模型返回 JSON 时反序列化为 `Briefing`（degraded=false），失败/未配置回退 mock 结构化简报（degraded=true）；done 事件按实际 `degraded`/`model` 输出。
- 配置：复用已有 `app.ai.enabled/mock/base-url/api-key/model/timeout`；docker-compose app 透传 `AI_BASE_URL/AI_API_KEY/AI_MODEL`；`.env.example` 已含这些变量。
- 决策说明：未引入 Spring AI 自动配置，改用 JDK HttpClient，避免“无 key 时启动失败”的强耦合，且零新增依赖；后续可平滑替换为 Spring AI `ChatClient`。
- 验证：`./gradlew :ai:test :alert:test :app:compileJava` 通过；`docker compose config -q` 通过。
- **待用户执行**：设置 `AI_BASE_URL`（如 `https://api.openai.com/v1` 或兼容端点）、`AI_API_KEY`、`AI_MODEL` 后重启；未设置时自动回退规则解析（前端 explanation 显示降级）。

## 2026-11-27 修复：scope=active 被误报为“无法映射字段”

- 现象：真实模型（DeepSeek）解析 `今天是否有pills相关告警` 返回 `scope:"active"`，前端显示“已忽略无法映射的字段：scope”。
- 根因：`QueryFilterMapper` 对 `scope` 一律记为 dropped，但 `scope=active` 正是当前读取端口的默认范围，应视为已满足。
- 修复：`QueryFilterMapper` 仅当 `scope != active`（如 history）才记为 dropped；`parseInstant` 增加 `OffsetDateTime` 回退，兼容模型返回 `+08:00` 等带偏移时间，避免静默丢弃 from/to。
- 测试：新增 `QueryFilterMapperTest`（scope active 不 dropped / history dropped / offset 时间解析 / 危险键拒绝）。
- 验证：`./gradlew :ai:test` 通过。
