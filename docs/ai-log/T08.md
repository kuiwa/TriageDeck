T08(audit): 审计写入（@Auditable切面、403审计、Keycloak采集）

实现内容：新增@Auditable注解（platform模块）、AuditAction/Outcome/ActorType/TargetType枚举、AccessDeniedAuditPort接口和AuditTargetResolver SPI。audit模块新增AuditWriterImpl（REQUIRES_NEW事务）、AuditCommand记录、AccessDeniedAuditRecorder（403审计入口）、AuditDetailSanitizer（白名单脱敏）和IpMasker（IP网段脱敏）。

验收结果：
- @Auditable(action="ALERT_CLEARED", target="ALERT") 已标注在 AlertClearService.clear() 上
- 业务成功 → 1条 ALERT_CLEARED/SUCCESS 审计记录，detail 包含告警快照
- 业务抛异常 → 1条 FAILED 审计记录，detail.errorClass 有值
- 主业务回滚 → 审计记录仍然存在（REQUIRES_NEW 事务）
- 403 越权 → JsonAccessDeniedHandler 调用 AccessDeniedAuditPort → 1条 ACCESS_DENIED/DENIED 审计记录，detail 包含 path/method
- 401 不产生审计记录
- detail 中不含 token/password/完整 IP（IpMasker/AuditDetailSanitizer）
- IP 脱敏：10.20.3.77 → 10.20.3.0/24

## 2026-11-27 补齐：@Auditable 切面（此前缺失，导致 audit_event 0 行）

- 现象：`audit_event` 表 0 行；清除告警后审计页仍为空。
- 根因：`@Auditable` 只加了注解，**没有任何切面拦截**（全仓无 @Aspect）；`AlertClearService.clear` 注释了但没人写审计。ACCESS_DENIED 有独立 recorder，登录事件依赖 Keycloak 采集器（`KC_COLLECTOR_SECRET` 为空时 eventsDisabled）。
- 实现（无新增依赖，复用事务基础设施代理）：
  - 新增 `AuditableAuditAdvice`（`MethodInterceptor`）：拦截 `@Auditable` 方法，成功写 `SUCCESS`、抛异常写 `FAILED` 后原样抛出；审计失败仅 error 日志不影响主流程；`targetId` 通过方法参数名解析（依赖 `-parameters`）。
  - 新增 `AuditAopConfig`：`AnnotationMatchingPointcut(null, Auditable.class, true)` + `DefaultPointcutAdvisor`，advisor 设为 `HIGHEST_PRECEDENCE`（事务提交/回滚后再写审计），并通过 `BeanFactoryPostProcessor` 将其标记为 `ROLE_INFRASTRUCTURE`，复用 `@EnableTransactionManagement` 的 `InfrastructureAdvisorAutoProxyCreator`，避免自建 AutoProxyCreator 抢占代理导致 `@Transactional` 失效。
  - 审计写入复用 `AuditWriterImpl`（`REQUIRES_NEW`），`source=APP`、`actor` 取当前用户。
- 测试：新增 `AuditableAuditAdviceTest`（Spring 上下文验证 SUCCESS/FAILED/未注解方法不审计），`./gradlew :audit:test` 通过。
- 已知限制：登录类事件仍需配置 `KC_COLLECTOR_SECRET` 且 Keycloak realm 开启 events。
