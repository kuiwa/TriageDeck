T06(alert): 清除告警

实现内容：新增 AlertClearService 与 AlertHistoryRepository，在单事务中执行 `INSERT INTO alerts_history ... cleared_fields` → `DELETE FROM alerts_active` 的原子操作。新增 Controller `POST /api/alerts/{id}/clear`，支持 reason 可空参数。
本次追加（前端）：AlertTable 增加「清除」操作列，仅拥有 `alert:clear` 权限的用户可见；点击后弹出确认对话框，支持填写清除原因；调用 `POST /api/alerts/{id}/clear`，成功后自动刷新活动列表与历史列表。

验收结果：
- 成功清除 → 200，history 中有对行且 cleared_at/cleared_by 填值
- 重复清除同一 ID → 409 ALREADY_CLEARED，history 仍仅 1 行
- 模拟 history insert 失败（PK 违例） → 事务回滚，active 仍存在
- 不存在的 ID → 404 ALERT_NOT_FOUND
- 无 reason 时也能成功（reason 可空 ≤500 字符）
- @Auditable(action="ALERT_CLEARED", target="ALERT") 已标注，切面在 T08 实现
- 前端：有 `alert:clear` 权限时显示清除按钮，无权限时隐藏；清除成功后活动和历史列表自动刷新
