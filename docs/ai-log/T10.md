## 改了什么

| 模块 | 文件 | 作用 |
|---|---|---|
| platform | `AlertIngestedMessage` / `AlertClearedMessage` | 消息契约 DTO（字段照 `02b-contract §6.3`） |
| platform | `DomainEventBus` | `publish` / `publishAfterCommit`（`TransactionSynchronization`，回滚不发） |
| platform | `ProcessedEventStore` | `tryMark(group, topic, partition, offset)`，`insert … on conflict do nothing`，不开事务 |
| platform | `KafkaErrorHandlingConfig` | `DefaultErrorHandler(FixedBackOff 1s×2)` + DLT 后缀取 `app.kafka.dlt-suffix` |
| alert | `AlertIngestListener` / `AlertKafkaConsumerService` | `alert.ingested` 消费（配置化 topic/group），幂等标记 + `AlertIngestService.ingest(cmd, KAFKA)` 同事务 |
| alert | `AlertHistoryRepository` / `AlertClearService` | 清除返回快照；提交后发 `alert.cleared`（key=alertId） |
| notify | `NotificationListener` / `NotificationConsumerService` | `alert.cleared` 消费 → `notification` 落库；删除旧 `NotifyConsumer`（硬编码 topic + stderr） |
| tools | `tools/device-simulator` | `:device-simulator`，`--mode=kafka|http --count=N`，Kafka 模式按 fingerprint 作 key |
| app | `application.yaml` | String 序列化/反序列化、`enable-auto-commit=false` |
| infra | `docker-compose.yml` | `kafka-init` 建 4 个 topic（主 + DLT）、`KAFKA_AUTO_CREATE_TOPICS_ENABLE=false`、app 依赖初始化完成 |
| 其他 | `security/CurrentActor` | 实现 `Principal#getName`，修掉 `cleared_by` 写成 `CurrentActor[...]` 的老问题 |

## 验收记录（本机 2026-11-27）

> 环境注记：本机 `*:9092` 已被一个本地 Kafka（PID 562）占用，docker kafka 的宿主端口实际不可达。
> 验收用 `bootRun`（`KAFKA_BOOTSTRAP_SERVERS=localhost:9092`）+ `:device-simulator:run` 连本地 broker，
> 消费者、SQL、幂等、DLT 行为与容器部署一致（容器内 broker 侧仅验证了 4 个 topic 可创建）。

| 项 | 命令/做法 | 结果 |
|---|---|---|
| 10 条 3 秒内入库 | `./gradlew :device-simulator:run --args="--count=10 --mode=kafka"` | `alert_event` 新增 10 行 `ingress=KAFKA`；3 个 fingerprint、`occurrence_count` 合计 +10；日志 `created=true/false` 交替 |
| 重复投递幂等 | `kafka-consumer-groups --reset-offsets --to-earliest` 后重启应用 | 10 条全部 `action=kafka_ingest_skipped`；`alerts_active` 与 `processed_event` 计数不变 |
| 非法 JSON → DLT | `printf '{"broken"' \| kafka-console-producer --topic alert.ingested` | 重试 2 次后 `alert.ingested.dlt` +1；`processed_event` 无该位点（事务回滚） |
| 清除发布 | `POST /api/alerts/{id}/clear` | `alert.cleared` 增长 1，`key=alertId`，消息体字段与 §6.3 一致 |
| 清除失败不发 | 重复清除（409）/未知 id（404） | `alert.cleared` 位点不变 |
| notify 落库 | 同上 | `notification` 每个成功清除 1 行，`payload.clearedBy=operator` |
| 单测 | `./gradlew :platform:test :alert:test :notify:test` | 11 个用例全绿（4 + 4 + 3） |
