# LLD 模板（lld/00-lld-template）

> 每册 LLD 必须严格按以下 9 节写，顺序与标题固定。写不出内容的小节要写「不适用 + 原因」，不能整节删除。
> 引用规则：字段/枚举/错误码只写「见 `02b-contract.md §x`」，**不复制定义**；行为与不变量写在本册。

## 1. 范围与边界

- 覆盖的 US 编号、承接的 T 编号。
- 本模块负责什么、明确不负责什么。
- 依赖方向（引用 `02-design.md §1.2`），对外暴露的端口/事件/注解。

## 2. 领域模型

- 实体 / 值对象 / 端口接口（不含实现）。
- 状态机（如活动→历史）与枚举映射（指向契约小节）。
- 关键不变量编号（`I-xx`，来自 `02-design.md §2`）；本册新增的用 `I-<模块>-<n>`。

## 3. 数据访问

- 用到的表（指向契约 §2.x）。
- 关键 SQL 原文（upsert / 原子移动 / 分页 / 导出），标注是否单语句、是否需要事务。
- 每个查询对应哪个索引；没有索引支撑的查询要写理由与实测计划。

## 4. 关键时序

3–5 条，覆盖：正常路径、并发、失败/回滚、下游失败。
用 mermaid `sequenceDiagram`；每条下面写「必须成立的断言」。

## 5. 接口清单

表格：端点编号（`#n`）、方法路径、权限、请求、返回、错误码。
**只写编号与要点，字段细节指向契约 §3。**

## 6. 事务与一致性

- 事务边界（哪个 public 方法、传播行为）。
- 跨事务协作（`REQUIRES_NEW` / `AFTER_COMMIT`）。
- 幂等键与并发控制手段（唯一索引 / 主键 / upsert），禁止的手段（应用锁）。

## 7. 错误与审计点

- 错误码映射表（异常类 → code → HTTP）。
- `@Auditable` 标注位置与 `targetType` / `targetId` 来源。
- 哪里不记审计以及原因（如 401、健康检查）。

## 8. 配置与运行

- 用到的配置键（向 `02b-contract.md §0.6`），默认值与必填环境变量。
- 启动期校验、失败降级行为、外部依赖不可用时的表现。
- 与 Docker/Kafka/Keycloak 的对接点。

## 9. 测试计划

| 类型 | 用例 | 覆盖 US | 覆盖 T | 「改坏必然红」的断言 |
|---|---|---|---|---|

- 单测必须能真实失败；集成测试继承 `ITBase`；造数走 `XxxFixtures`。
- 末尾给验收命令与预期输出。
