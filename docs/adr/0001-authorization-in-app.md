# ADR-0001 授权在应用内（Casbin），不设网关

- 状态：接受
- 日期：2026-11-23
- 影响：`security` 模块、`02b-contract.md §5`

## 背景

需求要求「改配置就能改权限」（US-A5）且「绕过界面直接调接口也要被拒」（US-A4）。可选方案：
在应用内做判定，或引入 API 网关集中鉴权。

## 决策

**在应用内用 Casbin（jcasbin）做判定**，策略与模型以文件形式打包进 jar；不引入任何网关。

- 请求三元组 `sub/obj/act`，匹配器只做精确相等。
- 所有 handler 必须标 `@RequirePermission`；无注解 = 403（默认拒绝）。
- 角色来自 JWT `realm_access.roles`，不同步进数据库。

## 理由

1. 演示要能「现场改 `policy.csv` → 重启 → 行为翻转」，文件化最直观。
2. 网关会把授权判断挪出可测范围（集成测试要起网关），与「每模块有测试」的约束冲突。
3. 单体部署，没有跨服务统一鉴权的需求。

## 后果

- 正：判定可单测、策略可评审、改权限不需要重建镜像（挂载配置或重启即可）。
- 负：策略变更需重启（US-A5 已按此口径验收）；多副本时策略文件要一致（本期单实例）。
- 明确不做：URL 通配（`keyMatch`）、把策略存 DB、把 Keycloak 用户同步进 Casbin。

## 替代方案

- 网关 + OPA：多一层运维与延迟，演示价值低。
- Spring Security 里硬编码角色判断：改权限要改代码，直接违反 US-A5。
