# ADR-0009 三条可选需求移入二期

- 状态：接受
- 日期：2026-11-23
- 影响：范围、`docs/traceability.md`、README 二期清单

## 背景

需求里明确标注「可选」的三条：US-B7（自动清除）、US-C6（审计哈希链）、US-D3（交接摘要）。
任务书 T01–T13 没有任何任务承接；而 T13 要求追溯矩阵「每条 US 都有落点，无空列」。

## 决策

三条**本期不做**，但保留数据结构与契约位：

| US | 本期状态 | 已留的铺垫 |
|---|---|---|
| US-B7 自动清除 | 二期 | `alerts_history.clear_mode`（`MANUAL/SYSTEM`）、`ActorType.SYSTEM`、`cleared_by='system'` 约定 |
| US-C6 哈希链 | 二期 | `audit_event` 无更新/删除路径；只需新增 `prev_hash/hash` 两列与校验端点 |
| US-D3 交接摘要 | 二期 | 契约 `#10` 位已写；`audit` 侧未来加 `AuditReadPort` |

追溯矩阵加 `状态` 列（`本期 / 二期`），不再用「空列」表达未做。

## 理由

1. 19 条必做已经能填满 8 分钟剧本（需求 §7 自检），三条可选不带来新的叙事价值。
2. US-C6 的并发串行化成本高于演示收益；US-B7 需要调度器与新的操作人语义。
3. 留列/留契约位比「以后再改表」便宜得多。

## 后果

- 正：范围收敛；追溯矩阵可完整；二期开工不需要改 DDL。
- 负：审计页不会出现「系统操作」记录（演示少一个亮点）——已用 `clear_mode` 说明清楚。
- 约束：主干代码不得留 TODO；二期项只出现在 README 清单与本 ADR。

## 替代方案

- 做 US-B7：需 +2h 起（调度 + 审计语义 + 测试），收益有限。
- 做 US-C6：需串行化写入，会拖慢审计写入路径。
